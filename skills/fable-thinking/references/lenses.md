# Lenses — 視野を強制的に広げる12のレンズ

Phase 3 で最低2つ選んで適用する。レンズの目的は「同じ場所から見続けること」を
物理的に不可能にすること。どれを選ぶか迷ったら、タスクの種類ごとの推奨セットを
末尾に示してある。

## 1. 時間軸レンズ

**問い:** この判断は今日・四半期後・2年後のそれぞれの時点でどう見えるか。

短期最適と長期最適が食い違うとき、その食い違い自体が論点になる。
「今は正しいが2年後に技術的負債になる」と言語化できれば、移行条件を先に決められる。

## 2. ステークホルダーレンズ

**問い:** この決定の影響を受けるのに、この議論の場にいないのは誰か。

運用担当、後任者、顧客、経理、監査。いない人の負担に転嫁する解は
一見エレガントに見えることが多い。

## 3. 逆転レンズ（inversion）

**問い:** この目標を確実に失敗させる方法を列挙せよ。いまの案はそのどれかを踏んでいないか。

「成功する方法」より「失敗する方法」のほうが列挙しやすく、網羅性も高い。
失敗リストの裏返しが要件になる。

## 4. 二次効果レンズ

**問い:** この解を適用したあと、次に何が起きるか。誰が適応し、その適応は何を壊すか。

一次効果で止まるのが浅い分析の典型。「通知を増やす → 見落としが減る」で止めず、
「通知が増える → 全部既読スルーになる → 重要通知も死ぬ」まで追う。

## 5. ベースレートレンズ

**問い:** 同種の試みは世間一般で何割成功しているか。自分のケースだけ特別だと信じる根拠は何か。

大規模リプレイス、締切前の「あと少し」、初回見積り。外側から見た統計は
内側から見た楽観をほぼ常に裏切る。

## 6. プレモーテム

**問い:** 半年後、この判断は失敗していたと想像する。何が起きたのか。物語として書く。

「リスクはありますか」と聞くと出てこない懸念が、「もう失敗しました。原因は?」と
聞くと出てくる。未来完了形は心理的な防御を外す。

## 7. 可逆性レンズ

**問い:** この判断は one-way door か two-way door か。

可逆な判断は速く決めて速く学ぶほうが得。不可逆な判断だけが慎重さに値する。
このレンズは深く考える対象を選別するためにも使える。Phase 0 のトリアージと対応する。

## 8. 機会費用レンズ

**問い:** これをやると決めることで、やらないと決まるものは何か。

工数・予算・注意力は有限。「やる価値があるか」ではなく
「他のどれよりも先にやる価値があるか」が本当の問い。

## 9. 制約緩和レンズ

**問い:** もし制約Xが消えたら解はどう変わるか。そもそもその制約は本物か。

「予算がないから」「システムが対応していないから」の中には、
確認すると既に消えている制約や、交渉可能な制約が混ざっている。

## 10. 根本原因レンズ

**問い:** いま解こうとしているのは症状か原因か。「なぜ」を5回続けたらどこに着くか。

症状への対処が正解の場面もある。ただし、それが症状への対処だと
自覚した上で選ぶのと、原因だと思い込んで選ぶのとでは再発時の対応が変わる。

## 11. スケールレンズ

**問い:** 対象が10倍になっても、この解は保つか。1/10だったら、この解は過剰ではないか。

10倍で破綻する解は、破綻する閾値と移行条件を先に書いておけば採用できる。
1/10で十分なら、いまの案はオーバーエンジニアリング。

## 12. 敵対者レンズ

**問い:** 悪意ある利用者・競合・攻撃者は、これをどう突くか。善意の利用者は、これをどう誤用するか。

セキュリティに限らない。入力の悪用、仕様の抜け道、インセンティブの歪み。
「誰も変なことはしない」前提の設計は、規模が出た瞬間に破れる。

## タスク種類ごとの推奨セット

| タスク | まず使うレンズ |
|--------|----------------|
| アーキテクチャ・技術選定 | 時間軸、スケール、可逆性 |
| 障害調査・トラブルシュート | 根本原因、二次効果 |
| 提案書・投資判断 | ベースレート、機会費用、プレモーテム |
| プロセス変更・運用設計 | ステークホルダー、二次効果、敵対者 |
| 要件定義・仕様策定 | 逆転、制約緩和、敵対者 |
| 見積り・計画 | ベースレート、プレモーテム、機会費用 |
