# Task Runner 導入ガイド

フォルダに置いたタスクチケットを、Claude（Cowork）が1時間ごとに1件ずつ処理して結果を書き戻す仕組みです。

## 導入（3ステップ）

1. **スキルを追加**：Claudeの設定画面からこのスキルを追加する。
2. **初期設定**：Coworkで作業用フォルダを選び、「task-runnerの初期設定をして」と依頼する。
   `tasks/` フォルダ、設定ファイル、サンプルタスク3件が作られます（最初は dry-run モード）。
3. **定期実行を登録**：Coworkのスケジュール実行に、1時間ごとで次のプロンプトを登録する。

   > task-runnerスキルで tasks フォルダのタスクを1件処理して

## お試しの流れ

1. 「task-runnerでタスクを1件処理して」と手動で3回実行 → dry-run なので計画が `## 結果` に書かれ、タスクは todo に戻ります。
2. `tasks/_config.md` の `mode` を `live` に変更。
3. もう一度3回実行 →
   - 売上集計 → `done/`（`tasks/output/sales_summary.md` ができる）
   - アジェンダ作成 → `done/`
   - 報告メール → `blocked/`（外部操作が「不可」なので、下書きを残して承認待ちになる）
4. `tasks/log.md` で毎回の動きを確認できます。

## ダッシュボード（看板ボード）

実行のたびに `tasks/dashboard.html` が自動で更新されます。ブラウザで開くと、未着手／実行中／要確認／完了の4列で状況が一目で分かります（ブックマークしておくと便利です）。

- 要確認のカードには止まった理由が赤字で出るので、まずそこを見れば人がやることが分かります。
- カードをクリックすると「計画カード」が開きます。やること、進め方の図、外部に触れる操作、AI が推測で決めたこと、**あなたが確認すべき点（最大3つ）** が1画面にまとまっています。
- 外部操作を許可したタスクは、実行前に計画カードを作って「計画の確認待ち」で止まります。確認点を見て問題なければ「未返信メールの下書き作成 OK」のように件名を添えて伝えると、次の回に実行されます。
- 手動で更新したいときは「タスクのダッシュボードを更新して」と頼むか、次を実行します。
  `python3 <スキルのフォルダ>/scripts/build_dashboard.py tasks`

## タスクの書き方

- `tasks/_template.md` をコピーして `tasks/todo/` に置くか、「〇〇のタスクを追加して」と頼む。
- ファイル名：`YYYYMMDD_優先度_件名.md`（例：`20260923_1_請求書チェック.md`）。日付が今日以前のものが対象、同日なら優先度の数字が小さい順。
- **完了条件は具体的に。** ここが曖昧だと正しく判定できません。
- メール送信などを自動で行わせたいときだけ `外部操作: 許可` にする。

## フォルダの意味

| フォルダ | 意味 | 人がやること |
|---|---|---|
| todo | 未着手 | タスクを置く |
| doing | 実行中 | 基本は触らない |
| blocked | 要確認・要承認 | 理由を読んで対応し、todoに戻す |
| done/YYYY-MM | 完了 | 結果を確認 |

## 注意

- Coworkはデスクトップアプリで動くため、PCがスリープ中やアプリ終了中は定期実行が動かないことがあります。
- 1回の起動で処理するのは1件だけです。件数が多い日は間隔を短くしてください。
- 途中で止まったタスク（doingに60分以上残ったもの）は、二重実行を避けるため自動で blocked に移ります。
